# ย้ายงานกล้อง CCTV จากหน้าเว็บไปไว้ในโปรแกรม (RRQCCamera.exe)

วันที่: 2026-10-02 · สถานะ: รอผู้ใช้ตรวจสเปก

## 1. เป้าหมาย

เดิมการเปิดกล้อง จับความเคลื่อนไหว และบันทึกคลิป ทำในหน้าเว็บ (`js/cctv.js`) ทำให้ต้องเปิด Chrome ค้างไว้ และเจอปัญหาภาพขาด/สีเพี้ยน/เปิดช้า/กล้องค้างกับ EMEET SmartCam S600 ที่ความละเอียดสูง

เป้าหมายใหม่:

1. โปรแกรมบนคอมเครื่องหลัก (`RRQCCamera.exe`) เป็นคนเปิดกล้อง ตรวจความเคลื่อนไหว และบันทึกคลิป ทำงานเบื้องหลังได้โดยไม่ต้องเปิดเบราว์เซอร์
2. หน้าเว็บเป็น "ที่ดูอย่างเดียว": ดูสด, ดูย้อนหลัง, สั่งหมุนภาพ
3. ใช้ได้กับกล้อง EMEET ที่ 1080p/2K ได้เสถียรกว่าเดิม

ตัดสินใจแล้วกับผู้ใช้: โปรแกรมทำกล้อง+บันทึก เว็บดูอย่างเดียว, ใช้ `ffmpeg.exe` วางไว้ข้างโปรแกรม (วิธีที่ "ดีสุด"), แยกเป็น exe ใหม่ ไม่รวมกับ `RRQCScanner.exe`

## 2. ขอบเขต

อยู่ในรอบนี้:

- `RRQCCamera.exe` (WinForms, C# 5, คอมไพล์ด้วย csc ที่มากับ Windows แบบเดียวกับตัวสแกนเนอร์) + `ffmpeg.exe` ที่ดาวน์โหลดมาวางข้างๆ
- เซิร์ฟเวอร์ HTTP ในโปรแกรม ใช้ในเครือข่ายเดียวกัน (LAN)
- แก้ `js/cctv.js`, `index.html`, `css/style.css` ให้หน้า CCTV เป็นหน้าดูอย่างเดียว

ไม่อยู่ในรอบนี้:

- ดูจากนอกเครือข่ายบ้าน (อินเทอร์เน็ต/TURN/tunnel)
- บัญชีผู้ใช้/ล็อกอิน (ใช้รหัสดูกล้องเหมือนเดิม)
- เสียงจากไมค์
- หลายกล้อง

## 3. สถาปัตยกรรม

```
กล้อง EMEET --DirectShow--> ffmpeg.exe (1 process, 2 outputs)
                               |-- out A: JPEG ต่อเนื่อง (stdout) ---> RRQCCamera.exe
                               |        |-- เซิร์ฟเวอร์ /live (MJPEG) ---> เว็บ/มือถือ (<img>)
                               |        '-- ย่อภาพ 160x120 ตรวจความเคลื่อนไหว
                               '-- out B: ท่อน mp4 10 วินาที ลงโฟลเดอร์พัก (buffer)
RRQCCamera.exe: ตัดสินใจว่าท่อนไหนเก็บ -> ย้ายเป็น motion_*.mp4 ในโฟลเดอร์คลิป
เว็บ <--HTTP /api/clips, /clips/<ชื่อ>.mp4 --- RRQCCamera.exe
```

### 3.1 ffmpeg (ต่อ 1 process)

- อินพุต: `-f dshow -video_size WxH -framerate F -vcodec mjpeg -i video="<ชื่อกล้อง>"` (โหมด MJPEG ลดแบนด์วิดท์ USB ที่เป็นต้นเหตุภาพขาด; ถ้ากล้องไม่มีโหมด MJPEG ที่ขนาดนั้น ถอยไปโหมดดิบอัตโนมัติ)
- ตัวกรองภาพ: หมุนตามค่าตั้ง (`transpose`), ฝังวันเวลามุมขวาล่าง (`drawtext`, ฟอนต์ Consolas ของ Windows)
- เอาต์พุต A (ดูสด + ตรวจเคลื่อนไหว): JPEG ~10 fps ขนาดไม่เกิน 1280 กว้าง ผ่าน `pipe:1`
- เอาต์พุต B (บันทึก): H.264 (`libx264 -preset veryfast -crf 26`), `-f segment -segment_time 10 -reset_timestamps 1 -strftime 1`, ชื่อ `seg_%Y-%m-%d_%H-%M-%S.mp4`, `movflags=+faststart` ให้เบราว์เซอร์เล่นได้
- ถ้า ffmpeg จบเอง หรือไม่มีเฟรมใหม่เกิน 8 วินาที: โปรแกรมฆ่าแล้วเปิดใหม่ (ลองซ้ำแบบถอยเวลา 1.5, 3, 6 วินาที ... สูงสุด 10 วินาที) แสดงสถานะและบันทึกลง log

### 3.2 ตัดสินใจเก็บท่อน (motion)

- ตรวจความเคลื่อนไหวจากภาพย่อ 160x120 ทุก ~220 ms ด้วยตรรกะเดียวกับเว็บเดิม (ค่า `pixelThreshold` และ `changedRatioThreshold` จากแถบความไว 1-10) พอร์ตมาจาก `checkMotion` ใน `js/cctv.js`
- ท่อน S เก็บถ้ามีการเคลื่อนไหวในท่อน S, หรือในท่อน S+1 (ภาพก่อนเริ่มเคลื่อนไหว = pre-roll), หรืออยู่ในช่วง "หยุดอัดหลังไม่มีการเคลื่อนไหว" (3/5/10 วินาที) หลังการเคลื่อนไหวล่าสุด
- ท่อนที่ไม่เข้าเงื่อนไขหลังเลยช่วงตัดสินใจ (ท่อนถัดไปจบแล้ว) ถูกลบ
- ท่อนที่เก็บ: ย้าย/เปลี่ยนชื่อเป็น `motion_YYYY-MM-DD_HH-mm-ss.mp4` (เวลาเริ่มจากชื่อ seg) ในโฟลเดอร์คลิปที่ผู้ใช้ตั้ง
- ตอนเปิดโปรแกรม ล้างไฟล์ค้างในโฟลเดอร์พักก่อนเริ่ม

### 3.3 เซิร์ฟเวอร์ HTTP

- เขียนเองบน `TcpListener` (ไม่ใช้ `HttpListener` เพราะการฟังที่อยู่ที่ไม่ใช่ localhost ต้องใช้สิทธิ์แอดมินหรือ `netsh urlacl`) พอร์ตเริ่มต้น 8787 แก้ได้ ฟังที่ทุกอินเทอร์เฟซ (มีตัวเลือกจำกัดแค่ localhost)
- Windows Firewall จะถามครั้งแรกตอนเปิดโปรแกรม ให้ผู้ใช้อนุญาต "เครือข่ายส่วนตัว"
- เส้นทาง (ทุกเส้นทางต้องมี `?k=<รหัสดูกล้อง>`):
  - `GET /live` MJPEG (`multipart/x-mixed-replace`) สำหรับ `<img>`
  - `GET /api/status` JSON: กล้องทำงานไหม ความละเอียดจริง/fps มุมหมุน
  - `GET /api/clips?from=<ms>&to=<ms>` JSON รายการคลิป `{name,start,end,size}` (เวลาเริ่มจากชื่อไฟล์ เวลาจบจากเวลาแก้ไขไฟล์ เหมือนเว็บเดิม)
  - `GET /clips/<ชื่อ>` ไฟล์คลิป รองรับ `Range` (ให้เลื่อนดูในตัวเล่นได้) และ `Content-Disposition` เมื่อมี `?dl=1`
  - `POST /api/rot?v=0|90|180|270` สั่งหมุนภาพ (ใช้กับหน้าเว็บ)
- CORS: ตอบ `Access-Control-Allow-Origin: *` และ `Access-Control-Allow-Private-Network: true` (ปลอดภัยเพราะทุกเส้นทางต้องมีรหัส)
- ความปลอดภัย:
  - รหัสดูกล้อง 8 ตัวสุ่มจาก `RandomNumberGenerator`, เทียบรหัสแบบเวลาคงที่, ผิดเกิน 10 ครั้ง/นาที/ที่อยู่ไอพี ตอบ 429 ชั่วคราว
  - ชื่อไฟล์คลิปรับเฉพาะรูปแบบ `^motion_\d{4}-\d{2}-\d{2}_\d{2}-\d{2}-\d{2}\.(mp4|webm)$` ป้องกัน path traversal ไม่มีการแสดงรายชื่อไดเรกทอรีอื่น
  - จำกัดจำนวนการเชื่อมต่อสดพร้อมกัน (4) และขนาด request header (เกิน 8 KB ปิดการเชื่อมต่อ)
  - ข้อเสียที่ยอมรับ: เป็น HTTP ไม่มี TLS ในเครือข่ายบ้าน รหัสวิ่งแบบไม่เข้ารหัสภายใน LAN (ผู้ใช้ต้องรู้)

### 3.4 หน้าต่างโปรแกรม (WinForms แบบเดียวกับ RRQCScanner)

- พรีวิวภาพสด, สถานะ (เปิดกล้อง/เฝ้าระวัง/กำลังบันทึก/กล้องค้างกำลังกู้), ความละเอียด/fps จริง
- ตั้งค่า: เลือกกล้อง, ความละเอียด (720p/1080p/2K ตามโหมดที่กล้องรองรับจริงจาก `-list_options`), fps (15/30), ความไว, หยุดอัดหลังไม่มีเคลื่อนไหว, การหมุนภาพ, โฟลเดอร์คลิป, พอร์ต, เก็บคลิปกี่วัน (ค่าเริ่มต้น 30 วัน ตามที่ผู้ใช้เคยตั้งกับประวัติสแกนเนอร์ — ยืนยันตอนตรวจสเปก; 0 = ไม่ลบ)
- แสดงรหัสดูกล้อง + ที่อยู่ (`http://<ไอพี>:8787`) + ปุ่มคัดลอก + ปุ่มสร้างรหัสใหม่
- ปุ่มเริ่ม/หยุดกล้อง, ซ่อนไปถาดระบบ, เปิดพร้อมวินโดวส์ (Registry `HKCU\...\Run` พร้อม `--tray`), single instance (mutex)
- ข้อมูลตั้งค่า/log ที่ `%APPDATA%\RRQC-Camera\` (`settings.ini`, `camera.log`)
- ลบคลิปเก่าอัตโนมัติวันละครั้งตามจำนวนวันที่ตั้ง (ลบเฉพาะไฟล์ชื่อ `motion_*` ในโฟลเดอร์คลิป)

### 3.5 ที่อยู่ของ ffmpeg

`ffmpeg.exe` วางข้าง `RRQCCamera.exe` (`tools/camera/ffmpeg.exe`) ไม่ commit ลง git (`.gitignore`) ดาวน์โหลด build "essentials" จาก gyan.dev ตรวจ SHA-256 ตามไฟล์ที่เว็บเดียวกันประกาศไว้ก่อนใช้ **ต้องขออนุญาตผู้ใช้ก่อนดาวน์โหลด** โปรแกรมถ้าไม่เจอ `ffmpeg.exe` จะแสดงข้อความบอกวิธีวาง

## 4. หน้าเว็บ (ฝั่งดู)

- ลบจาก `js/cctv.js`: การเปิดกล้อง (`getUserMedia`), ตรวจความเคลื่อนไหว, `MediaRecorder`, เลือกโฟลเดอร์, ยามเฝ้ากล้อง, ปรับแสง/ความละเอียด, WebRTC host/viewer, สลับบทบาท
- เหลือ/ปรับ:
  - **กล้องสด:** `<img src="http://<host>:<port>/live?k=<รหัส>">` + ช่องใส่ที่อยู่/รหัส (จำใน localStorage; ถ้าเปิดหน้าเว็บจากที่อยู่เดียวกับโปรแกรมให้เติมที่อยู่ให้เอง) + ป้ายสถานะจาก `/api/status` + ปุ่มเต็มจอ + เลือกการหมุนภาพ (ส่ง `POST /api/rot`)
  - **ดูย้อนหลัง:** ไทม์ไลน์/ปุ่มลัด/ก่อนหน้า-ถัดไป/ดาวน์โหลด ใช้ของเดิม แต่ดึงรายการและไฟล์จาก `/api/clips` และ `/clips/...` แทนการอ่านโฟลเดอร์/WebRTC (ตัดการโหลดทั้งไฟล์เข้าหน่วยความจำ ใช้ `<video src>` ตรงๆ พร้อม Range)
- ถ้าติดต่อโปรแกรมไม่ได้ แสดงข้อความชัดเจน (โปรแกรมไม่ได้เปิด/อยู่คนละ Wi-Fi/รหัสผิด/Firewall)
- ข้อจำกัด: หน้าเว็บที่โฮสต์บน `https://` (เช่น GitHub Pages) เรียก `http://` ใน LAN ไม่ได้ (mixed content) ต้องเปิดเว็บแบบ `http://` ผ่าน `start-cctv.bat` เหมือนปัจจุบัน

## 5. ข้อมูลเดิม

- คลิปเก่า `.webm` ในโฟลเดอร์เดิมยังแสดงในไทม์ไลน์ได้ (เซิร์ฟเวอร์รับทั้ง `motion_*.webm` และ `motion_*.mp4`)
- ค่าตั้งเดิมใน localStorage ของเว็บไม่ถูกย้าย ผู้ใช้ตั้งใหม่ในโปรแกรมครั้งเดียว

## 6. การทดสอบ/ตรวจรับ

- โหมดทดสอบ `--test-source` ใช้ตัวสร้างภาพจำลองของ ffmpeg (`lavfi testsrc` + ส่วนที่เคลื่อนไหวเป็นช่วงๆ) แทนกล้องจริง เพื่อทดสอบตรรกะบันทึก/ตรวจเคลื่อนไหว/เซิร์ฟเวอร์ โดยไม่ขึ้นกับกล้อง
- ตรวจอัตโนมัติ (สคริปต์ PowerShell): ท่อนที่มีเคลื่อนไหวถูกเก็บพร้อม pre-roll, ท่อนที่ไม่มีถูกลบ, ชื่อไฟล์ตรงรูปแบบ, `/api/clips` ตรงกับไฟล์จริง, `/clips` รองรับ Range, รหัสผิดได้ 401, ชื่อไฟล์แปลก (`..\`) ได้ 400/404, `/live` ส่งเฟรม JPEG ที่ถอดรหัสได้
- ตรวจด้วยกล้อง EMEET จริงบนเครื่องนี้: เปิดที่ 720p/1080p/2K ดูว่าภาพไม่ขาด, สถานะ fps จริงตรงที่ตั้ง, ปิดกล้อง/ถอดสายแล้วกู้เอง
- ตรวจหน้าเว็บในเบราว์เซอร์ในแอป: ดูสด/ย้อนหลังต่อกับโปรแกรมที่รันโหมดทดสอบ

## 7. ความเสี่ยงและทางออก

| ความเสี่ยง | ทางออก |
|---|---|
| ffmpeg dshow เปิดกล้อง EMEET ที่ 2K/MJPEG ไม่ได้ | ถอยโหมดดิบอัตโนมัติ, แสดงโหมดที่กล้องรองรับจริง, แจ้งผู้ใช้ |
| ภาพขาดที่ต้นทาง (พอร์ต/สาย USB) | โปรแกรมแก้ฮาร์ดแวร์ไม่ได้ แต่แสดง fps จริงเพื่อให้วินิจฉัยได้; ปัญหานี้เห็นแล้วในหน้า Settings ของ Windows |
| Firewall บล็อกพอร์ต | แสดงข้อความแนะนำพร้อมวิธีอนุญาต, ปุ่มทดสอบการเชื่อมต่อในเว็บ |
| CPU/ดิสก์หนักที่ 2K | ค่าเริ่มต้น 1080p/15 fps, ปรับ `crf`/preset ผ่านไฟล์ตั้งค่า, ลบคลิปอัตโนมัติ |
| รหัสวิ่งแบบไม่เข้ารหัสใน LAN | ยอมรับสำหรับเครือข่ายบ้าน แจ้งผู้ใช้; รอบหน้าถ้าต้องการนอกเครือข่ายค่อยเพิ่ม TLS/tunnel |

## 8. ลำดับการทำ (ร่างสำหรับแผน)

1. ขออนุญาต + ดาวน์โหลด ffmpeg ตรวจ SHA-256, ทดลองเปิดกล้อง EMEET ด้วยคำสั่ง ffmpeg ตรงๆ เพื่อยืนยันโหมด 1080p/2K (ลดความเสี่ยงก่อนเขียนโปรแกรม)
2. แกนโปรแกรม: ตั้งค่า, คุม ffmpeg, อ่าน JPEG, ตรวจเคลื่อนไหว, ตัดสินใจเก็บท่อน
3. เซิร์ฟเวอร์ HTTP + ความปลอดภัย
4. หน้าต่าง/ถาดระบบ/เปิดพร้อมวินโดวส์/ลบคลิปเก่า
5. แก้หน้าเว็บให้เป็นฝั่งดู
6. ทดสอบตามหัวข้อ 6, อัปเดต README, commit (ยังไม่ push จนกว่าผู้ใช้สั่ง)
